# Moneta Lite v0.3.1 — mantenimiento

- Los permisos de Django Admin quedan limitados al propietario para el personal ordinario. El guardado y el borrado de movimientos y facturas conservan los saldos y asientos en una sola operación atómica.
- La cola de importaciones valida al revisor, la moneda y la cuenta de destino. PostgreSQL serializa la deduplicación y la revisión concurrente. El reintento de aprobación conserva el mismo resultado.
- Se retiran del paquete las rutas, vistas, plantillas, JavaScript, catálogo comercial y comando de ejecución de las funciones Pro. El registro manual de suscripciones y seguros y los CSV de movimientos y facturas siguen disponibles. MCP conserva sus 15 herramientas y `get_upcoming_bills` devuelve vencimientos de suscripciones y seguros del usuario.
- Las tablas, campos, restricciones y migraciones históricas se conservan. Los movimientos y asientos ya registrados permanecen en la base. Las reglas históricas de ejecución automática dejan de ejecutarse y permanecen almacenadas con sus datos originales. Cambiar `SAAS_EDITION` siempre carga Lite.

## Actualización desde v0.3.0

1. Respalda la base y la configuración. Detén el proceso web y cualquier tarea programada que siga usando el código de v0.3.0, incluido `manage.py run_recurring`.
2. Instala la versión revisada en un directorio nuevo y conserva las variables `DB_*` y `DJANGO_SECRET_KEY` de la instalación. Apunta SQLite al archivo existente mediante `DB_NAME` o usa la conexión PostgreSQL existente.
3. Instala las [dependencias](../../INSTALL.md) y ejecuta `python manage.py migrate --noinput`. Si el despliegue sirve archivos recolectados, ejecuta `python manage.py collectstatic --clear --noinput` con el `STATIC_ROOT` dedicado a Moneta.
4. Inicia la aplicación y comprueba cuentas, movimientos, facturas y saldos con tu usuario. La interfaz de suscripciones permite actualizar manualmente las fechas de vencimiento.

CI ejecuta `scripts/check_v030_upgrade.sh` en SQLite y PostgreSQL. El script usa el tag público original, crea datos de prueba, verifica un saldo y asientos balanceados y compara todas las filas de finanzas después de la actualización. Para ejecutarlo en PostgreSQL, usa una base vacía y desechable.

## Exportación y sincronización hacia Lite

Usa el árbol público revisado como origen de los paquetes Lite. Para aportar cambios compartidos desde otro producto, revisa y aplica el parche mínimo en una rama local del repositorio Lite. Evita las copias recursivas o fusiones de árboles completos. Antes de publicar una rama, revisa la procedencia y el contenido del diff, incluidos cambios en rutas ya permitidas. Comprueba la lista de archivos con `python scripts/check_lite_tree.py` una vez preparado el índice, ejecuta las pruebas con `SAAS_EDITION=pro` y verifica el árbol y su historial con Gitleaks. Una ruta nueva requiere revisión explícita y actualización de `scripts/lite-files.txt`; CI comprueba el manifiesto, las firmas conocidas de módulos comerciales, los permisos en ejecución y los 15 contratos MCP. Genera el paquete desde el commit público aprobado con `git archive`.
